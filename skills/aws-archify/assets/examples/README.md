# Worked examples

Complete scenes built with the layout engine, from a small starter to large multi-tier architectures, so you can see
how real designs are composed and reuse the patterns. Each is a `.tsx` scene with its rendered `.svg`. Every one was
looked at, not just passed through the report: the SVG was exported to PNG and checked for arrow crossings, overlaps,
label overflow and landscape balance.

The scenes are the architectures in the table below and two engine canaries (last section) that give
`npm run examples` coverage of the engine's absolute-placement half. Copy the architectures, not the canaries.

Captions use the official AWS service names ("Amazon API Gateway", "AWS Lambda", "Amazon DynamoDB", "AWS CodeBuild",
"Amazon ECR", "Amazon CloudWatch") with the node's role in the `sub` line. A few keep a role name as the caption
("Authorizer", "Tx signer", "Tenant router", "Model registry") where the role matters more than the service; on a new
figure follow the naming rule in [composition.md](../../references/composition.md).

## Working on one

Render to a scratch path, so the `.png` and `.drawio` the render also writes do not land in this folder:

```bash
npm run watch -- assets/examples/<name>.tsx --svg /tmp/<name>.svg     # re-renders on every save
npm run render -- assets/examples/<name>.tsx /tmp/<name>.svg          # one render; Read the look copy it prints
```

To refresh the committed SVGs after an engine change, use `npm run examples`
([engine-regression.md](../../references/engine-regression.md)).

Start with **`serverless-api.tsx`**: the smallest end-to-end scene (Users, then API Gateway, Lambda and DynamoDB in
nested AWS Cloud, Region and VPC boxes), built only from layout primitives with id-attached arrows and no coordinates.
It is the quality to reach before tackling the larger ones.

Patterns that recur across the examples (hubs that fan out or fan in, labels at the open end of an arrow, padding a
box so a label lands inside it, a `<Spacer>` to straighten a hop into a container, a shared absolute `riser` for a
fan-out) are written up once in [arrows.md](../../references/arrows.md). Every example carries its flow on short
italic arrow labels and none uses numbered steps; why is in the same guide.

## Kept advisories

still carry 25 advisories (WARN lines) between them:

Only the first five are kept on purpose. The others predate the layout WARN rules: copy those scenes' DSL, not those
parts of their layout, and treat the same WARNs as must-fix on a figure of your own.

One more thing not to copy: the Payments box in `web3-payments-oauth.tsx` is a `kind="region"` box labelled
"Payments". A box for a logical concern is `kind="generic"`; a `region` box must be labelled as a Region
([composition.md](../../references/composition.md)).

## Engine canaries, not style examples

Two scenes exist for the regression gate (`npm run examples`), not as patterns. Without them every example would be
pure layout, and the engine's absolute half (free placement, hand-drawn connectors) would be invisible to the gate: a
change to it would produce no `.svg` diff at all.

- **`canary-primitives.tsx`**: a hand-placed video-on-demand pipeline using the escape hatches no architecture needs:
  `layout="free"` and `<Free>` with `x`/`y`, `<Icon>` with a separate `<Label>`, `<Rect>`, `<Raw>`, `<ZStack>`,
  `<Spacer>`, `<Move>`, `<Anchor>`, `points` with `edges()`, `via` and `riser`. Its `<Move>` wraps two tiles (Amazon
  CloudWatch and AWS X-Ray), which stay side by side in their row, nudged down together. It renders clean.
- **`canary-nested-group-snap.tsx`**: a `<VStack>` whose wide caption pushes an `<HStack>`-wrapped `<Group>` onto a
  half-grid offset, which used to make the layout's grid verification throw. A Group's absolute origin is now snapped
  when it is placed, so the scene renders clean; it stays as the canary for that snap.

What each one guards is detailed in [engine-regression.md](../../references/engine-regression.md). Both are real
architectures on the 8 px grid, so `clean` stays a meaningful target for them. Do not reach for their escape hatches in
an ordinary figure: structure first, absolute coordinates only to mirror a reference image.

## The layout lesson behind all of them

The biggest single driver of a clean complex figure is placing connected components next to each other, so arrows are
short and never cross an icon or a caption. Arrows that cross in an X over a caption mean the nodes they join are not
lined up: an early draft of the e-commerce figure drew its WAF to ALB to Storefront arrows as an X across the ALB
label. The current scene lines those three up in one column (fixed-width cells, and a blank cell in the public subnet),
so each hop is a straight drop. Prefer a landscape, left-to-right flow (an aspect of 4:3 to 16:9, about 1.33 to 1.78), let the Groups
hug their contents, and keep tiers aligned with `<Grid>`, `<HStack>` and `<VStack>`.
