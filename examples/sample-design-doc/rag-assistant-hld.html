1.Introduction

1.1.Purpose

Teams lose time searching approved internal documents for answers. This design adds an assistant that answers questions from those documents only, with each answer grounded in retrieved passages. It asks the reader to approve a retrieval-augmented design on Amazon Bedrock with a separate ingestion path.

1.2.Scope and assumptions

In scope. The question-and-answer path for signed-in users, and the path that adds and retires documents in the index.

Out of scope. Writing or approving the documents themselves, which stays with each content owner.

Assumptions. Documents stay in the team's own storage, and the assistant reads only what has been indexed. Appendix C lists what still has to be confirmed.

2.Architecture

Figure 1 shows the whole solution: the retrieval path on the left and the ingestion path on the right.

The main components:

  • Entry point (Amazon CloudFront, Amazon Cognito, Amazon API Gateway): users reach the assistant over HTTPS, sign in, and call the API.
  • Orchestrator (AWS Lambda): retrieves passages and asks the model for an answer.
  • Knowledge base (Amazon Bedrock, Amazon OpenSearch Service): the foundation model and the vector index it answers from.
  • Conversation store (Amazon DynamoDB): the chat history for each conversation.
  • Ingestion (Amazon S3, AWS Step Functions, Amazon Textract, AWS Lambda): turns each document into indexed passages.

3.How the design works

3.1.Retrieval path

A signed-in user sends a question through Amazon API Gateway, which checks the Amazon Cognito token. An AWS Lambda function retrieves the closest passages from the vector index in Amazon OpenSearch Service. It then asks a foundation model in Amazon Bedrock to answer from those passages only, keeping the conversation in Amazon DynamoDB.

3.2.Ingestion path

An AWS Step Functions workflow takes each document placed in Amazon S3 and extracts its text with Amazon Textract. It then chunks and embeds the text and writes it to the index. Retiring a document runs the same workflow, which deletes the document's chunks from the index.

3.3.Identity and data protection

AreaDesign
IdentityUsers sign in to an Amazon Cognito user pool; API Gateway accepts only requests carrying a valid token (NFR1)
EncryptionDocuments in Amazon S3 are encrypted at rest; the platform team decides whether to use its own AWS KMS key
Model dataModel providers have no access to the prompts and completions the assistant sends
Content safetyAn Amazon Bedrock guardrail filters harmful input and model responses
RetentionConversation items carry a TTL; DynamoDB deletes them in the background after expiry, so retention is at least the TTL, not exactly it

3.4.Failure handling

FailureDetectionResponse
A long answer runs past the API integration timeoutAPI Gateway returns a timeout error to the userRetrieved passages and response length are capped (NFR2)
An ingestion step failsThe Step Functions execution reports the errorThe workflow retries the step, then catches the failure so the document is not half indexed

7.AWS references

  • Control access to REST APIs using Amazon Cognito user pools as an authorizer - API Gateway accepts only tokens from the user pool
  • Quotas for configuring and running a REST API in API Gateway - the 29 second integration timeout, adjustable for Regional and private APIs
  • Inference using Converse API - multi-turn requests to a foundation model
  • Amazon Bedrock: data protection - model providers have no access to customer prompts and completions
  • Detect and filter harmful content by using Amazon Bedrock Guardrails - filtering of harmful user input and model responses
  • k-Nearest Neighbor (k-NN) search in Amazon OpenSearch Service - nearest-neighbour search over knn_vector fields
  • Calling Amazon Textract Asynchronous Operations - the asynchronous API for multipage PDF and Tagged Image File Format (TIFF) documents
  • Handling errors in Step Functions workflows - retry and catch on a failed ingestion step
  • Using server-side encryption with Amazon S3 managed keys (SSE-S3) - every new object upload is encrypted with SSE-S3 by default
  • Using time to live (TTL) in DynamoDB - expired items are deleted in the background after expiry, not at the expiry time

A. Do's and don'ts

DoDon't
